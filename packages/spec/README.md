# Spec — Deterministic SDD & Verification Engine for AI Coding Agents

**Spec** is a deterministic governance and Spec-Driven Development (**SDD**) harness at repository scope for autonomous AI coding agents and software engineers.

---

## 🎯 Purpose & Overview

Delegating complex engineering tasks to AI coding agents often breaks down due to underspecified requirements, test false-positives, and uncontrolled file mutations across unrelated codebases.

`spec` enforces a strict, honest lifecycle:
```
init ──► agent install ──► preflight ──► new ──► plan ──► tasks ──► work ──► verify ──► finish
```

### Safety & Quality Invariants
1. **Strict Path Boundaries**: All writes and subprocess execution directories are confined strictly below the explicit project root after resolving symlinks.
2. **Cryptographic Ownership Tracking**: Autogenerated files (`AGENTS.md`, `.spec/ownership.json`) are tracked by SHA-256 digests. Spec never overwrites unowned user files.
3. **Deterministic `argv` Verification**: Verification checks are declared as explicit JSON argument arrays (e.g. `["pytest", "-q"]`). They never pass through a shell interpreter (`sh`/`bash`), preventing variable leaks or injection attacks.
4. **Zero Tolerance for False Positives**: `SKIPPED`, `INCOMPLETE`, or `ERROR` statuses (including timeouts and missing CLI binaries) **never** count as `PASS`.
5. **Atomic Seal (`finish`)**: The `finish` command succeeds strictly when the latest recorded verification report in `.spec/evidence/` is an authentic `PASS`.

pip install -e packages/spec

## 🏛️ Internal Architecture

Spec is designed in 5 strictly unidirectional layers:

```
packages/spec/
├── src/spec/
│   ├── core/                  # Path boundaries, atomic writes, SHA-256 ownership,
│   │                          # TUI, and PreflightManager (Git worktree isolation)
│   ├── governance/            # Repository policy, formal audit (audit.py),
│   │                          # and craftsmanship evaluation (judge.py)
│   ├── spec/                  # SDD state machine (workflow.py), @s scenario
│   │                          # traceability (trace.py), and TDD assist (assist.py)
│   ├── verify/                # Deterministic verification engine (engine.py) and
│   │                          # zero-dependency AST mutation testing (mutate.py)
│   ├── agents.py              # Universal AGENTS.md governance adapter
│   └── cli.py                 # Master CLI dispatcher
├── skills/                    # Agent skills (spec-new, spec-plan, spec-verify, spec-finish)
└── tests/                     # Unit and end-to-end test suites
```

### Persisted Repository State (`.spec/`)

| Path | Purpose | Manually Editable? |
| --- | --- | :---: |
| `.spec/policy.json` | Project boundaries, governance policies, and invariants | **Yes** |
| `.spec/verification.json` | Explicit JSON `argv` commands, required checks, and timeouts | **Yes** |
| `.spec/state.json` | State machine snapshot of the active feature | **No** (CLI managed) |
| `.spec/ownership.json` | SHA-256 content digests of files Spec may update or delete | **No** |
| `.spec/specs/<feature>/` | Feature artifacts: `spec.md`, `plan.md`, `tasks.md`, `work.md` | **Yes** (Human / Agent) |
| `.spec/evidence/<feature>/`| Immutable, append-only verification reports on disk | **No** (Sealed evidence) |
| `AGENTS.md` | Universal governance standard for all AI coding agents | **No** (Generated by `spec agent`) |

## 📖 Practical Guide & The Complete SDD Lifecycle

### Step 1: Health Diagnostics & Repository Initialization
In any target project repository:
```bash
# 1. Verify Spec runtime diagnostics
spec doctor

# 2. Initialize the repository-local .spec/ governance structure
spec init --root /path/to/project

# 3. Install the reversible agent adapter (AGENTS.md)
spec agent install --root /path/to/project
```

---

### Step 2: Pre-Flight Baseline & Git Worktree Isolation (`spec preflight`)
Before introducing dirty changes or new branches, validate baseline tests and isolate work in a worktree:
```bash
spec preflight "user-auth" --from "main" --branch "feature/user-auth" --worktree --root /path/to/project
```
- Validates that the base branch compiles and current baseline tests pass.
- Provisions an isolated Git Worktree with dependency symlinks.
- Outputs the working directory path where the agent must execute.

---

### Step 3: Formal Specification (`spec new`)
Define functionality with explicit, observable acceptance criteria:
```bash
spec new "user-auth" --description "JWT authentication with token rotation"
```
Generates `.spec/specs/user-auth/spec.md`. Each acceptance scenario must be tagged with stable identifiers (`@s1`, `@s2`, etc.) in Gherkin format (`Given / When / Then`).

---

### Step 4: Technical Architecture & Task Breakdown (`spec plan` & `spec tasks`)
```bash
# 1. Generate architectural implementation plan scaffold
spec plan

# 2. Breakdown atomic development tasks
spec tasks
```
Produces `plan.md` (architectural decisions, file modifications) and `tasks.md` (ordered atomic tasks mapped to `@s` scenarios).

---

### Step 5: Test-First Assisted Implementation (`spec work` & `spec test-assist`)
```bash
# Formally enter the active coding phase
spec work

# Get guidance on the next uncovered @s scenario to implement in unit tests
spec test-assist --next
```

---

### Step 6: Deterministic Verification (`spec verify`)
Declare test commands in `.spec/verification.json`:
```json
{
  "schema_version": 1,
  "checks": [
    {
      "id": "unit-tests",
      "command": ["pytest", "-q"],
      "required": true,
      "timeout_seconds": 300
    },
    {
      "id": "linter",
      "command": ["ruff", "check"],
      "required": true,
      "timeout_seconds": 60
    }
  ]
}
```
Run verification:
```bash
spec verify
# Or with JSON output for automated pipelines:
spec verify --json
```
Each run produces an immutable audit report in `.spec/evidence/<feature>/`.

---

### Step 7: Advanced Quality (Mutation Testing, Audit & Judge)

#### Zero-Dependency Mutation Testing (`spec mutate`)
Evaluates test suite rigor by injecting syntax mutations into the Python AST:
```bash
spec mutate src/auth/token.py --test-cmd "pytest -q" --max 50 --threshold 90.0
```

#### Repository Audit (`spec audit`)
Verifies scenario traceability, untracked files, and artifact completeness:
```bash
spec audit
```

#### Craftsmanship Evaluation & Verdict ("The Judge")
```bash
# Record an approval verdict
spec judge --approve --remarks "Clean architecture, zero over-engineering"

# Or request modifications
spec judge --reject --remarks "Missing tests for token expiration scenario"
```

---

### Step 8: Completion & Sealing (`spec finish`)
```bash
spec finish
```
Verifies that the latest recorded verification status was strictly `PASS` and seals the feature as completed.

---

### Clean Adapter Uninstallation
To remove `AGENTS.md` or other adapters without leaving unowned files:
```bash
# Dry-run preview (default)
spec agent uninstall

# Apply deletion after SHA-256 ownership digest validation
spec agent uninstall --apply
```
