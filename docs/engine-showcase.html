01 / Del Prompt Artesanal a Ingeniería Multi-Agente

Ya usás agentes en Orca.
Ahora dales un motor que no improvisa.

Una skill en Markdown le pide al agente que se porte bien. ia-spec-ops-engine se acopla a tu sesión en Orca para que todo lo verificable corra en Python (ai-governance + ws) y vos te concentres en diseñar y aprobar lo importante.

Orca-First Orquesta workers reales de Claude, Codex y Antigravity en tus worktrees.
5 Etapas Pre-push gate veloz: valida solo lo que modificaste antes de subir el PR.
Contexto Puro Condensa builds y tests ruidosos para que tu coordinador no pierda el foco.
Fail-Closed Si falta un recibo de Orca, cambia un hash o se cuela un modelo, frena solo.
Por qué lo adopta el equipo: cero copiar y pegar prompts entre pestañas de Orca, menos idas y vueltas en CI/PRs y un piso técnico compartido sin frenar tu velocidad local.
02 / Para el dev escéptico del "Con mi Skill me alcanza"

¿Qué pasa cuando dependés solo de un SKILL.md?

Tocá cualquiera de estos 5 incidentes reales en Orca y compará qué pasa con una skill suelta frente a tener el Engine vigilando por debajo.

Solo con SKILL.md

El worker arranca igual con otro modelo

La skill pide usar cierto modelo o nivel de razonamiento, pero si el coordinador omite el flag o Orca hace fallback, el worker corre con otro modelo y nadie lo detecta.

Orca + ia-spec-ops-engine

Validado al lanzar y verificado en launch.json

taskflow.denied_models bloquea antes del dispatch y al recolectar abre launch.json de Orca para comprobar qué agente y modelo corrieron realmente. 

AI_GOVERNANCE_DENIED_MODELS="gemini-3.8-flash" ai-governance taskflow debate T1 open ...
→ ERROR: seat 'antigravity': model 'gemini-3.8-flash' is denied by taskflow.denied_models (exit 1)
03 / Arquitectura Neural + Determinística

Orca ejecuta los workers. El Engine pone las reglas y la memoria.

El motor nunca reemplaza a Orca ni lanza agentes por su cuenta: prepara los specs, imprime el orca orchestration worker-start exacto y verifica el resultado cuando Orca termina.

Orca · Capa de ejecución

Worktrees limpios y coordinación sin polling manual

Orca crea y aísla los workspaces de cada worker, despierta a tu sesión coordinadora cuando llega worker_done y emite el recibo firmado en launch.json que luego audita el Engine. 

# El Engine arma el spec y te da la línea exacta para Orca:
orca orchestration worker-start --spec-file .../runs/001/spec.md \
  --agent antigravity --model gemini-3.8-flash --effort low \
  --worktree path:/tu/repo --task-title 'debater round 1' --json > launch.json

Cuando un build o test vuelca 4.000 líneas en la terminal de Orca, el agente se distrae, compacta antes de tiempo y pierde el hilo. ws run corta ese ruido de raíz.

  log_id: run_20261116_2104 · 148 KB guardados
  para buscar detalle: ws log run_20261116_2104 --grep "FAILED|ERROR"
Menos compactación

Sesiones más largas y lucidas

Tu coordinador en Orca conserva la arquitectura en mente en lugar de llenarse con warnings repetidos.

Cero re-corridas

Log completo siempre a mano

Si hace falta investigar una falla puntual, corrés ws log <id> --grep sin relanzar el suite.

Visibilidad

05 / Cero Sorpresas en el PR

Quality Gate veloz en cada worktree + límites de diseño

Con gate.scope = "changed", el pre-push valida en segundos solo los archivos que modificaste, mientras la suite completa corre en CI. Convive sin conflictos con Husky o hooks propios.

Etapas del Pre-Push Gate
Etapa Qué evita antes de llegar al PR Estado
1. SecretsSubir API keys o tokens con gitleaksPASS
2. Git PoliciesPushear a main o romper commitsPASS
3. Lintersruff, mypy, eslint según tu stackPASS
4. Design LimitsFunciones gigantes o complejas (Lizard)PASS
5. Test SuitesTests afectados por tus cambios realesPASS
ws design --changed

Chau funciones de 200 líneas generadas por IA

Controla complejidad ciclomática (≤ 10), largo (≤ 40 líneas) y tests vacíos ("junk tests"). Usa ratchet: el código viejo no te frena, pero lo nuevo entra prolijo. 

$ ws design --changed
Pre-existing: 1 warning (non-blocking)
✔ design: PASS (19 files, 0 blocking violations)
06 / Orquestación Multi-Agente en Orca

taskflow: el que programa no se auto-aprueba

Tu sesión en Orca actúa como builder. Cuando necesitás validar un plan o juzgar cambios, taskflow obliga a que validator y judge corran en otro proveedor en Orca.

Cero sesgo

Cruce real de modelos

Anti-deriva

Huella Git sellada

Continuidad

Retomá en otra sesión

taskflow here recupera pasos, hechos, decisiones y aprobaciones al instante.

07 / Novedad v2.3.0 · taskflow debate en Orca

Debate de diseño multi-proveedor antes de escribir código

¿Tenés una decisión técnica difícil? Poné a debatir 2 o más proveedores en Orca. El Engine coordina tesis, repreguntas cruzadas y una síntesis matemática sin que tengas que copiar nada a mano.

Fase 1 · Aislamiento + Hashes

Tesis independientes en paralelo dentro de Orca

Cada asiento recibe la misma pregunta, su propia carpeta scratch/ para correr scripts de prueba y las instrucciones de --web / --artifact.

  • Exige al menos 2 proveedores distintos (el debater puede compartir proveedor con builder).
  • Sella topic_sha y SHA-256 de cada artifact en debate.json.
taskflow debate mi-diseno open \
  --topic-file tema.md \
  --agents codex,antigravity,claude \
  --web --artifact src/models.py

→ Imprime 3 líneas `orca orchestration worker-start ...`
→ Cada worker corre aislado en Orca sin ver a los demás
08 / Confiabilidad en Equipo

Seguros internos para que nada falle en silencio

Cuando varios devs corren workers en Orca en paralelo, los casos borde aparecen solos. El Engine está diseñado fail-closed: ante la duda frena limpio y te explica exactamente qué pasó.

Políticas de Modelos

denied_models + --effort

  • Un repositorio nunca puede relajar la lista de modelos prohibidos del usuario; solo agregar.
  • Si la config está mal formada o falta el modelo en launch.json de Orca, collect rechaza la ronda.
  • --effort se valida siempre junto con un modelo explícito o por defecto.
Concurrencia & Rollback

Locks separados y cero basura en disco

  • Lock propio .debate.lock separado de .lock del store (sin interbloqueos).
  • Lectura no bloqueante de archivos regulares (O_NONBLOCK + S_ISREG).
  • Si un dispatch en Orca falla a mitad de camino, hace rollback de rondas y sellos.
Resultado para el equipo: no dependés de que cada persona recuerde mil flags; el repo y tu configuración local garantizan las mismas reglas en cada worker de Orca.

10 / Sumate en 2 Minutos

Cómo instalarlo y usarlo en tu setup con Orca

Cada persona del equipo instala los dos paquetes una sola vez con uv tool, activa los hooks no invasivos y ya puede lanzar rondas o debates directo desde su sesión en Orca. 

# 1. Instalar ambas CLIs desde el repo (en modo editable si usás packs/skills locales)
uv tool install --editable ./packages/ai-governance
uv tool install --editable ./packages/workspace

# 2. Instalar reglas para tus agentes y hooks de pre-push en tu repo
ai-governance install --scope user --agent all
ws hooks install

# 3. Verificar que todo esté sano y listo para Orca
ai-governance doctor && ws doctor

# 4. Abrir tu primer debate multi-proveedor desde Orca
ai-governance taskflow new mi-diseno --title "Definir estrategia de cache"
ai-governance taskflow debate mi-diseno open --topic-file tema.md --agents claude,antigravity --web
